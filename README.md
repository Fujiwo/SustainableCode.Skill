# サステナブルコード Skill

## 概要

`sustainable-code-jp` は、人間とAIの双方が理解し変更し続けられるコード「サステナブルコード」の判断基準を、AIエージェントが実践できるようにする日本語版の Skill である。書籍『サステナブルコード』(小島富治雄 著、翔泳社)の原稿をもとに、設計・実装・命名・テスト・リファクタリング・レビューのベストプラクティスをまとめている。

## 適用する原則

原則は三層からなる。

- **最上位の価値: Think Simple(YAGNI・引き算の設計)**: 複雑な問題は解かず、必要になってから作る。何を作らないか、何を削るかを決める。
- **四つの武器**: Think Simple を支える「境界を分けて名前を付ける」「意図を What として表す」「検証できる形に置く」という三つの動きを、次の四つで実践する。
  - **七箇条**: 意図を表現、単一責務の原則、的確な名前付け、Once And Only Once、的確に記述されたメソッド、ルールの統一、Testable を一体として適用する。
  - **Name and Conquer**: 注目すべきものを見つけて名前を付け、他から切り分けて問題を支配する。
  - **SON(サービス指向名前付け)**: 使う側の視点で名前を決める。
  - **Testable な設計**: 正しく書かれていることが分かる構造にし、フィードバックを最大化する。
- **支える技法**:
  - **コードの臭いと技法**: 劣化の兆候を臭いとして名指しし、対応する技法を選ぶ。
  - **契約とガード節**: 前提条件・事後条件・不変条件をコードに刻む。

## 適用される作業

この Skill は、プログラミング言語を問わず、ソースコードを書く・変える・評価する作業を利用条件としている。対象には、コードを書く前の設計相談も含まれ、SQL やシェルスクリプトもコードとして扱う。小さな修正でも軽く適用するように指示している。Claude Code は `description` と依頼の関連性から Skill を選ぶため、対象作業でも毎回の自動選択を保証するものではない。

文書の誤字修正、git 操作だけ、環境構築、ライブラリの使い方の質問、コードの説明・読解だけ、設定値の変更だけ、CI やビルドの設定ファイルだけの編集は、利用条件から外している。コードを評価するレビューとは区別する。正確な条件は SKILL.md の `description` を参照。

## Skill の振る舞い

この Skill は、原則の適用に加えて、次の進め方を指示する。読み込みの成功と指示への遵守は別であり、差分と検証結果は利用者が確認する。

- **作業規模に応じて軽重を変える**: 設計判断も仕様の解釈も要らない小さな変更では、末尾のセルフチェックだけを適用する。判断を伴う作業(機能追加、設計、リファクタリング、レビューなど)では、作業の種類に応じた reference を読む。
- **決まった型で完了報告をする**: What(何を変えたか)、Why(なぜそう書いたか)、作らなかったもの、検証結果、範囲外の気づき、ユーザーの判断が要る点を報告する。
- **変更範囲を守る**: 依頼された範囲の外はリファクタリングせず、気づいた臭いは名前を挙げて報告するにとどめる。
- **上位のルールに従う**: 優先順位は、ユーザーの明示的な指示、CLAUDE.md などエージェント向けの指示、リポジトリのコーディング規約、既存コードベースの流儀、この Skill の順である。

## 構成

- `SKILL.md`: 前提、行動原則、作業規模に応じた適用の軽重、優先順位、原則が対立したときの判断ルール、セルフチェック
- `references/`: 作業の種類ごとに必要なときだけ読む詳細。`foundations.md`(美しいコードと七箇条)、`naming.md`(命名)、`modeling.md`(モデリング)、`paradigms.md`(パラダイムの使い分け)、`object-design.md`(オブジェクトの設計)、`testing.md`(テスト)、`refactoring.md`(リファクタリング)、`simplicity.md`(Think Simple)、`quality-gates.md`(レビュー・規約・契約・性能)、`collaboration.md`(タスク理解・質問・報告)

## 公開状況

この Skill は、GitHub で公開している。ライセンスは MIT で、詳細は[ライセンス](#ライセンス)の節と `LICENSE` ファイルを参照。

- 配布元: https://github.com/Fujiwo/SustainableCode.Skill

使うには、リポジトリを `git clone` するか ZIP でダウンロードし、`sustainable-code-jp` フォルダーを、使いたいプロジェクトの `.claude/skills/` にコピーする。`SKILL.md` は `references/` 配下のファイルを参照するため、フォルダーごとコピーすること。

## 使い方

- **自動選択**: 関連する依頼で、Claude Code が `description` に基づいてこの Skill を選ぶことがある。
- **明示**: 本書の判断基準を使ってほしいときは、メッセージの先頭で `/sustainable-code-jp` と名前を指定して呼び出す。

配置先は対象プロジェクトのルートにある `.claude/skills/sustainable-code-jp/`。GitHub Copilot in VS Codeでは `.github/skills/sustainable-code-jp/` への配置も利用できる。配置後は、Skillの一覧や呼び出し・ファイル参照の履歴で、確認できる範囲を確かめる。製品が表示する方法は、利用する版の公式資料に従う。

読み込みを確認しても、指示どおりのコードが生成される保証にはならない。要求との一致、変更差分、検証結果から採否を決める。導入と評価の説明は、書籍原稿の[付録A](../原稿/appendix-a.md)を参照。
